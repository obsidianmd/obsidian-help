Obsidian позволяет перенести ваши данные из Airtable с помощью [[Импортёр|плагина Импортёр]]. Он преобразует ваши базы Airtable в долговечные файлы Markdown, которые вы можете использовать офлайн с Obsidian и многими другими приложениями.

Каждая таблица превращается в папку заметок, где каждая запись — отдельная заметка, плюс файл [[Введение в Базы|Базы]], который воссоздаёт таблицу и её представления. Поскольку используется API Airtable, для импорта требуется персональный токен доступа и подключение к интернету.

## Создание персонального токена доступа Airtable

Для доступа к данным Airtable через API вам нужен персональный токен доступа. Этот шаг занимает около двух минут.

Токен — это длинная строка из цифр и букв, обычно начинающаяся с `pat...`, которая позволит вам скачать ваши данные из Airtable.

1. Войдите в Airtable и перейдите на страницу [Personal access tokens](https://airtable.com/create/tokens) в настройках вашего аккаунта.
2. Выберите **Create new token**.
3. Дайте токену имя, например «Obsidian». Можно использовать любое имя.
4. В разделе **Scopes** добавьте `data.records:read` и `schema.bases:read`.
5. В разделе **Access** добавьте базы, которые хотите импортировать, или выберите все базы в рабочем пространстве.
6. Выберите **Create token**, затем **Copy**, чтобы скопировать токен.
7. Сохраните токен в безопасном месте, например в менеджере паролей.

Airtable показывает токен только один раз. Если вы его потеряете, создайте новый.

## Импорт данных из Airtable

Вам понадобится официальный плагин Obsidian [[Импортёр]], который можно [установить здесь](obsidian://show-plugin?id=obsidian-importer).

1. Откройте **[[Настройки]]**.
2. Перейдите в **Плагины сообщества** и [установите Импортёр](obsidian://show-plugin?id=obsidian-importer).
3. Включите плагин Импортёр.
4. Откройте плагин **Импортёр** с помощью палитры команд или значка на вертикальной панели.
5. В поле **File format** выберите **Airtable**.
6. В поле **Airtable Personal Access Token** нажмите **Link...**, чтобы добавить новый секрет. В поле **ID** укажите имя, например `airtable`, а в поле **Secret** вставьте ваш персональный токен доступа.
7. Нажмите **Загрузить**, чтобы просмотреть ваши базы, затем выберите таблицы для импорта.
8. Просмотрите и отредактируйте параметры импорта.
9. Нажмите **Import**, чтобы настроить преобразование полей в заметки со [[Свойства|свойствами]].
10. Нажмите **Продолжить**, чтобы просмотреть сгенерированный шаблон и примеры записей.
11. Нажмите **Import** и дождитесь завершения импорта.

## Параметры импорта

- **Convert formulas** — выберите, будут ли поля формул, lookup, rollup и count переписаны как [[Формулы|формулы Баз]] (с откатом к значению, вычисленному Airtable, при отсутствии эквивалента) или импортированы только как статические значения.
- **Загружать вложения** — сохранение файлов вложений в ваше хранилище с использованием настроек папки вложений и формата ссылок. Если опция отключена или загрузка не удалась, заметка ссылается на URL файла на Airtable.
- **View property name** — свойство, в котором записывается, к каким представлениям Airtable принадлежит запись. Каждое представление в сгенерированной Базе фильтрует по этому свойству. По умолчанию — `Views`.
- **Save Airtable record ID** — добавляет свойство `airtable-id`, чтобы при последующих импортах можно было распознать записи после перемещения или переименования их заметок.

## Настройка импорта полей Airtable

На этапе настройки полей вы можете выбрать, как импортируется каждое поле.

По умолчанию каждое поле Airtable становится свойством. Вы можете переименовать или удалить свойства и изменить их значения перед переходом к предварительному просмотру шаблона.

Первичное поле каждой таблицы используется как название заметки по умолчанию. Вы можете изменить шаблон названия заметки на этапе предварительного просмотра. Записи всегда помещаются в папку, названную по имени таблицы.

См. [[Шаблоны импортёра]] для настройки сгенерированного Markdown.

## Что импортируется

Для базы с именем `Projects` с таблицей `Tasks` импортёр создаёт:

```
Airtable/
	Projects/
		Tasks.base
		Tasks/
			Write the proposal.md
			Review the draft.md
```

- По одной заметке на запись, с первичным полем в качестве названия заметки и остальными полями записи в виде [[Свойства|свойств]].
- Файл `.base` для каждой таблицы, где каждое представление Airtable сопоставляется с [[Виды|представлением Баз]]:
	- **Grid** становится [[Таблица|табличным представлением]].
	- **Gallery** становится [[Карточки|представлением карточек]].
	- **List** становится [[Список|представлением списка]].
	- **Kanban** становится [[Канбан|представлением канбан]] в Obsidian 1.14 и новее. Airtable не указывает, по какому полю сгруппирован канбан, поэтому после импорта [[Канбан#Группировка карточек по столбцам|выберите свойство для группировки]]. При повторном импорте ваш выбор сохраняется.
- Типы полей Airtable сопоставляются с типами свойств Obsidian без перезаписи типов, которые вы уже настроили.
- Связанные записи становятся ссылками на соответствующие заметки.
- Вложения загружаются в ваше хранилище с использованием настроек хранилища.


## Ограничения

Из-за ограничений скорости API Airtable импорт больших баз может занять значительное время. Пожалуйста, будьте терпеливы.

Из-за ограничений API Airtable некоторые данные недоступны или не могут быть преобразованы:

- Значения rollup не импортируются. API не предоставляет информацию об агрегации, использованной для вычисленного значения rollup, поэтому записывается только имя свойства вместе с формулой Баз, если схема поля содержит выражение.
- Формулы, использующие функции, для которых в Obsidian нет эквивалента, такие как `SWITCH`, `FIND`, `REGEX_EXTRACT` и `SQRT`, используют статическое значение из Airtable.
- Импортируются только представления grid, gallery, list и kanban. Другие типы представлений, такие как calendar, timeline и Gantt, игнорируются.
- Ссылки на записи в таблицах, которые вы не выбрали, становятся обычным названием записи, а не ссылкой.
- Дизайны интерфейсов, автоматизации, комментарии и история изменений не импортируются.
