Obsidian에서는 [[들여오기|들여오기 플러그인]]을 사용하여 Airtable에서 데이터를 마이그레이션할 수 있어요. 이 과정에서 Airtable 베이스가 내구성 있는 Markdown 파일로 변환되어 Obsidian 및 다른 많은 앱에서 오프라인으로 사용할 수 있어요.

각 테이블은 레코드당 하나의 노트로 구성된 폴더가 되며, 테이블과 그 보기를 재현하는 [[베이스 소개|베이스]] 파일이 함께 생성돼요. Airtable API를 사용하기 때문에 가져오기에는 개인 액세스 토큰과 인터넷 연결이 필요해요.

## Airtable 개인 액세스 토큰 만들기

API를 통해 Airtable 데이터에 접근하려면 개인 액세스 토큰이 필요해요. 이 단계는 약 1분 정도 걸려요.

토큰은 보통 `pat...`으로 시작하는 긴 문자열로, Airtable에서 데이터를 다운로드할 수 있게 해줘요.

1. Airtable에 로그인하고 계정 설정의 [Personal access tokens](https://airtable.com/create/tokens) 페이지로 이동하세요.
2. **Create new token**을 선택하세요.
3. 토큰에 이름을 지정하세요. 예를 들어 "Obsidian"으로 지정할 수 있어요. 아무 이름이나 사용할 수 있어요.
4. **Scopes** 아래에 `data.records:read`와 `schema.bases:read`를 추가하세요.
5. **Access** 아래에 가져오려는 베이스를 추가하거나, 작업 공간의 모든 베이스를 선택하세요.
6. **Create token**을 선택한 다음 토큰을 **Copy**하세요.
7. 비밀번호 관리자와 같은 안전한 곳에 토큰을 저장하세요.

Airtable은 토큰을 한 번만 표시해요. 분실한 경우 새로 만들어야 해요.

## Airtable 데이터 가져오기

공식 Obsidian [[들여오기]] 플러그인이 필요하며, [여기에서 설치](obsidian://show-plugin?id=obsidian-importer)할 수 있어요.

1. **[[설정]]**을 여세요.
2. **커뮤니티 플러그인**으로 이동하고 [들여오기를 설치](obsidian://show-plugin?id=obsidian-importer)하세요.
3. 들여오기 플러그인을 활성화하세요.
4. 명령어 팔레트 또는 리본 아이콘을 사용하여 **들여오기** 플러그인을 여세요.
5. **파일 형식** 아래에서 **Airtable**을 선택하세요.
6. **Airtable Personal Access Token** 아래에서 **연결...**을 클릭하여 새 비밀을 추가하세요. **ID**에는 `airtable`과 같은 이름을 지정하고, **비밀** 항목에 개인 액세스 토큰을 붙여넣으세요.
7. **불러오기**를 클릭하여 베이스를 탐색한 다음 가져오려는 테이블을 선택하세요.
8. 가져오기 옵션을 검토하고 편집하세요.
9. **Import**를 선택하여 필드가 [[속성]]이 있는 노트로 어떻게 변환될지 설정하세요.
10. **계속**을 클릭하고 가져오기가 완료될 때까지 기다리세요.
11. 완료됐어요!

### 가져오기 옵션

- **Convert formulas** — 수식, 조회, 롤업, 카운트 필드를 [[수식|베이스 수식]]으로 다시 작성할지 선택해요. 동등한 수식이 없을 경우 Airtable이 계산한 값으로 대체하며, 또는 정적 값으로만 가져올 수도 있어요.
- **첨부파일 다운로드** — 첨부 파일을 보관함에 저장하며, 첨부 파일 폴더 및 링크 형식 설정을 사용해요. 비활성화하거나 다운로드가 실패하면 노트에서 Airtable의 파일 URL로 링크해요.
- **View property name** — 레코드가 어떤 Airtable 보기에 속하는지 기록하는 속성이에요. 생성된 베이스의 각 보기는 이 속성으로 필터링해요. 기본값은 `base`예요.
- **Incremental import** — 각 노트에 `airtable-id` 속성을 추가하여 이후 가져오기 시 이미 가져온 레코드를 건너뛸 수 있어요. 전체 가져오기 시에는 이 속성이 다시 제거돼요.

## Airtable 필드 가져오기 방식 설정

가져오기의 두 번째 단계에서 각 필드가 어떻게 가져와지는지 선택할 수 있어요.

테이블의 각 필드에는 `{{field_name}}`이라는 변수가 지정돼요. 기본적으로 모든 필드는 속성이 되며, 이 변수를 사용하여 속성 이름을 바꾸거나, 값을 변경하거나, 각 노트의 본문에 콘텐츠를 작성할 수 있어요.

각 테이블의 기본 필드는 항상 노트 제목으로 사용되며, 레코드는 항상 테이블 이름을 딴 폴더에 배치되므로 이 옵션은 변경할 수 없어요.

## 가져오는 항목

`Projects`라는 베이스에 `Tasks` 테이블이 있는 경우, 들여오기는 다음과 같이 생성해요:

```
Airtable/
	Projects/
		Tasks.base
		Tasks/
			Write the proposal.md
			Review the draft.md
```

- 레코드당 하나의 노트가 생성되며, 기본 필드가 노트 제목으로 사용되고 나머지 필드는 [[속성]]으로 저장돼요.
- 테이블당 하나의 `.base` 파일이 생성되며, 각 Airtable 보기가 [[보기|베이스 보기]]에 매핑돼요:
	- **Grid**는 [[표 뷰]]가 돼요.
	- **Gallery**는 [[카드 뷰]]가 돼요.
	- **List**는 [[목록 뷰]]가 돼요.
	- 기타 모든 보기 유형은 표 뷰로 변환돼요.
- Airtable 필드 유형이 Obsidian 속성 유형에 매핑되며, 이미 설정한 유형은 덮어쓰지 않아요.
- 연결된 레코드는 해당 노트로의 링크가 돼요.
- 첨부 파일은 보관함 설정을 사용하여 보관함에 다운로드돼요.

## 제한 사항

> [!info] Airtable 가져오기는 새 기능이에요
> Airtable 들여오기는 새로운 기능이에요. 변환 과정에서 문제가 발생하면 [버그 리포트를 제출](https://github.com/obsidianmd/obsidian-importer/issues)해 주세요. 개선하는 데 도움이 돼요.

Airtable API 속도 제한으로 인해 대용량 베이스를 가져올 때 상당한 시간이 걸릴 수 있어요. 기다려 주세요.

Airtable API의 제한으로 인해 일부 데이터를 사용할 수 없거나 변환할 수 없어요:

- 롤업 값은 가져오지 않아요. API가 롤업의 계산된 값에 사용된 집계 방식을 노출하지 않기 때문에, 속성 이름만 작성되며 필드 스키마가 표현식을 노출하는 경우 베이스 수식이 함께 포함돼요.
- Obsidian에 동등한 함수가 없는 함수를 사용하는 수식(예: `SWITCH`, `FIND`, `REGEX_EXTRACT`, `SQRT`)은 Airtable의 정적 값으로 대체돼요.
- Grid, Gallery, List 보기만 가져와요. Calendar, Kanban, Timeline, Gantt 등 기타 보기 유형은 무시돼요.
- 선택하지 않은 테이블의 레코드에 대한 링크는 링크 대신 레코드의 일반 텍스트 제목이 돼요.
- 인터페이스 디자인, 자동화, 댓글, 수정 기록은 가져오지 않아요.
