Obsidian ช่วยให้คุณย้ายข้อมูลจาก Airtable ได้โดยใช้[[ตัวนำเข้า|ปลั๊กอินตัวนำเข้า]] ซึ่งจะแปลง Airtable bases ของคุณเป็นไฟล์ Markdown ที่คงทนถาวร ใช้งานออฟไลน์ได้กับ Obsidian และแอปอื่นๆ อีกมากมาย

แต่ละตารางจะกลายเป็นโฟลเดอร์ของโน้ตที่มีหนึ่งโน้ตต่อหนึ่งเรคคอร์ด พร้อมด้วยไฟล์[[แนะนำฐาน|ฐาน]]ที่สร้างตารางและมุมมองขึ้นมาใหม่ เนื่องจากใช้ Airtable API การนำเข้าจึงต้องมี personal access token และการเชื่อมต่ออินเทอร์เน็ต

## สร้าง Airtable personal access token

ในการเข้าถึงข้อมูล Airtable ผ่าน API คุณต้องมี personal access token ขั้นตอนนี้ใช้เวลาประมาณ 2 นาที

Token คือสตริงยาวของตัวเลขและตัวอักษร โดยทั่วไปจะเริ่มต้นด้วย `pat...` ซึ่งจะอนุญาตให้คุณดาวน์โหลดข้อมูลจาก Airtable

1. เข้าสู่ระบบ Airtable แล้วไปที่หน้า [Personal access tokens](https://airtable.com/create/tokens) ในการตั้งค่าบัญชีของคุณ
2. เลือก **Create new token**
3. ตั้งชื่อ token ของคุณ เช่น "Obsidian" สามารถใช้ชื่อใดก็ได้
4. ใต้ **Scopes** ให้เพิ่ม `data.records:read` และ `schema.bases:read`
5. ใต้ **Access** ให้เพิ่ม bases ที่คุณต้องการนำเข้า หรือเลือก bases ทั้งหมดในพื้นที่ทำงาน
6. เลือก **Create token** จากนั้น **Copy** token
7. บันทึก token ไว้ในที่ปลอดภัย เช่น ตัวจัดการรหัสผ่านของคุณ

Airtable จะแสดง token เพียงครั้งเดียว หากคุณทำหาย ให้สร้างใหม่

## นำเข้าข้อมูล Airtable ของคุณ

คุณจะต้องใช้ปลั๊กอิน [[ตัวนำเข้า]] อย่างเป็นทางการของ Obsidian ซึ่งคุณสามารถ[ติดตั้งได้ที่นี่](obsidian://show-plugin?id=obsidian-importer)

1. เปิด **[[การตั้งค่า]]**
2. ไปที่ **ปลั๊กอินโดยชุมชน** แล้ว[ติดตั้ง Importer](obsidian://show-plugin?id=obsidian-importer)
3. เปิดใช้งานปลั๊กอิน Importer
4. เปิดปลั๊กอิน **Importer** โดยใช้กระดานคำสั่งหรือไอคอนริบบอน
5. ใต้ **File format** เลือก **Airtable**
6. ใต้ **Airtable Personal Access Token** คลิก **Link...** เพื่อเพิ่มความลับใหม่ สำหรับ **ID** ให้ตั้งชื่อ เช่น `airtable` และสำหรับ **Secret** ให้วาง personal access token ของคุณ
7. คลิก **โหลด** เพื่อเลือกดู bases ของคุณ จากนั้นเลือกตารางที่คุณต้องการนำเข้า
8. ตรวจสอบและแก้ไขตัวเลือกการนำเข้า
9. เลือก **Import** เพื่อตั้งค่าวิธีแปลงฟิลด์ของคุณเป็นโน้ตที่มี[[คุณสมบัติ]]
10. เลือก **ดำเนินการต่อ** เพื่อตรวจสอบเทมเพลตที่สร้างขึ้นและดูตัวอย่างจากเรคคอร์ดของคุณ
11. เลือก **Import** แล้วรอจนกว่าการนำเข้าจะเสร็จสมบูรณ์

## ตัวเลือกการนำเข้า

- **Convert formulas** — เลือกว่าฟิลด์ formula, lookup, rollup และ count จะถูกเขียนใหม่เป็น[[สูตร|สูตรฐาน]] โดยใช้ค่าที่ Airtable คำนวณไว้เมื่อไม่มีสูตรที่เทียบเท่า หรือนำเข้าเป็นค่าคงที่เท่านั้น
- **ดาวน์โหลดไฟล์แนบ** — บันทึกไฟล์แนบลงในห้องนิรภัยของคุณ โดยใช้การตั้งค่าโฟลเดอร์ไฟล์แนบและรูปแบบลิงก์ เมื่อปิดใช้งาน หรือเมื่อดาวน์โหลดล้มเหลว โน้ตจะลิงก์ไปยัง URL ของไฟล์บน Airtable แทน
- **View property name** — คุณสมบัติที่บันทึกว่าเรคคอร์ดอยู่ในมุมมอง Airtable ใดบ้าง แต่ละมุมมองในฐานที่สร้างขึ้นจะกรองตามคุณสมบัตินี้ ค่าเริ่มต้นคือ `Views`
- **Save Airtable record ID** — เพิ่มคุณสมบัติ `airtable-id` เพื่อให้การนำเข้าครั้งถัดไปสามารถจดจำเรคคอร์ดได้หลังจากที่โน้ตถูกย้ายหรือเปลี่ยนชื่อ

## ตั้งค่าวิธีนำเข้าฟิลด์ Airtable

ในขั้นตอนการตั้งค่าฟิลด์ คุณสามารถเลือกวิธีนำเข้าแต่ละฟิลด์ได้

โดยค่าเริ่มต้น ทุกฟิลด์ Airtable จะกลายเป็นคุณสมบัติ คุณสามารถเปลี่ยนชื่อหรือลบคุณสมบัติ และเปลี่ยนค่าก่อนดำเนินการต่อไปยังการดูตัวอย่างเทมเพลต

ฟิลด์หลักของแต่ละตารางจะถูกใช้เป็นชื่อโน้ตเริ่มต้น คุณสามารถแก้ไขเทมเพลตชื่อโน้ตจากขั้นตอนดูตัวอย่าง เรคคอร์ดจะถูกวางไว้ในโฟลเดอร์ที่ตั้งชื่อตามตารางเสมอ

ดู [[เทมเพลตตัวนำเข้า]] เพื่อปรับแต่ง Markdown ที่สร้างขึ้น

## สิ่งที่ถูกนำเข้า

สำหรับ base ชื่อ `Projects` ที่มีตาราง `Tasks` ตัวนำเข้าจะสร้าง:

```
Airtable/
	Projects/
		Tasks.base
		Tasks/
			Write the proposal.md
			Review the draft.md
```

- หนึ่งโน้ตต่อหนึ่งเรคคอร์ด โดยฟิลด์หลักเป็นชื่อโน้ต และฟิลด์อื่นๆ ของเรคคอร์ดเป็น[[คุณสมบัติ]]
- ไฟล์ `.base` หนึ่งไฟล์ต่อตาราง โดยแต่ละมุมมอง Airtable จะถูกแปลงเป็น[[มุมมอง|มุมมองฐาน]]:
	- **Grid** จะกลายเป็น[[มุมมองตาราง]]
	- **Gallery** จะกลายเป็น[[มุมมองการ์ด]]
	- **List** จะกลายเป็น[[มุมมองรายการ]]
	- **Kanban** จะกลายเป็น[[มุมมองคัมบัง]]ใน Obsidian 1.14 ขึ้นไป Airtable ไม่ได้ระบุว่า kanban จัดกลุ่มตามฟิลด์ใด ดังนั้น[[มุมมองคัมบัง#จัดกลุ่มการ์ดเป็นคอลัมน์|เลือกคุณสมบัติที่จะใช้จัดกลุ่ม]]หลังจากนำเข้า การนำเข้าอีกครั้งจะคงการเลือกของคุณไว้
- ประเภทฟิลด์ Airtable จะถูกแปลงเป็นประเภทคุณสมบัติของ Obsidian โดยไม่เขียนทับประเภทที่คุณตั้งค่าไว้แล้ว
- Linked records จะกลายเป็นลิงก์ไปยังโน้ตที่เกี่ยวข้อง
- ไฟล์แนบจะถูกดาวน์โหลดลงในห้องนิรภัยของคุณโดยใช้การตั้งค่าของห้องนิรภัย


## ข้อจำกัด

เนื่องจากข้อจำกัดอัตราการใช้งาน Airtable API การนำเข้า bases ขนาดใหญ่อาจใช้เวลานานมาก กรุณาอดทนรอ

เนื่องจากข้อจำกัดใน Airtable API ข้อมูลบางส่วนไม่สามารถเข้าถึงหรือแปลงได้:

- ค่า Rollup จะไม่ถูกนำเข้า API ไม่เปิดเผยการรวมค่าที่ใช้สำหรับค่าที่คำนวณของ rollup ดังนั้นจะเขียนเฉพาะชื่อคุณสมบัติ พร้อมด้วยสูตรฐานเมื่อ schema ของฟิลด์เปิดเผย expression
- สูตรที่ใช้ฟังก์ชันที่ Obsidian ไม่มีสิ่งเทียบเท่า เช่น `SWITCH`, `FIND`, `REGEX_EXTRACT` และ `SQRT` จะใช้ค่าคงที่จาก Airtable แทน
- เฉพาะมุมมอง grid, gallery, list และ kanban เท่านั้นที่ถูกนำเข้า ประเภทมุมมองอื่นๆ เช่น calendar, timeline และ Gantt จะถูกข้ามไป
- ลิงก์ไปยังเรคคอร์ดในตารางที่คุณไม่ได้เลือกจะกลายเป็นชื่อเรคคอร์ดแบบข้อความธรรมดาแทนที่จะเป็นลิงก์
- Interface designs, automations, ความคิดเห็น และประวัติการแก้ไขจะไม่ถูกนำเข้า
