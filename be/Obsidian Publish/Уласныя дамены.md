Для свайго сайта [[Уводзіны ў Obsidian Publish|Obsidian Publish]] вы можаце наладзіць уласны дамен або паддамен.

> [!warning] Увага
> Цяпер мы падтрымліваем наладу ўласных даменаў толькі наступнымі спосабамі:
>
> - [[#Налада праз CloudFlare]] у [рэжыме Full](https://developers.cloudflare.com/ssl/origin-configuration/ssl-modes/full/).
> - [[#Налада праз проксі]]
> 
> Пакуль у нас няма магчымасці выпусціць SSL-сертыфікат за вас.

## Налада праз CloudFlare

Самы просты спосаб наладзіць уласны дамен або паддамен — стварыць уліковы запіс [CloudFlare](https://cloudflare.com) і даверыць CloudFlare кіраванне DNS вашага дамена.

Наступныя крокі паказваюць, як з дапамогай CloudFlare наладзіць уласны дамен для сайта Obsidian Publish — кораневы дамен (`mysite.com`) або паддамен (`notes.mysite.com`).

> [!important] Важна
> CloudFlare — **адзіны афіцыйна падтрыманы правайдар** для налады ўласных даменаў. З іншымі правайдарамі гэтыя інструкцыі, хутчэй за ўсё, не спрацуюць.

**CloudFlare:**

1. Адкрыйце ў Cloudflare дамен, на якім хочаце размясціць сайт Publish, напрыклад `mysite.com`, нават калі вам патрэбны паддамен накшталт `notes.mysite.com`.
2. Перайдзіце ў **DNS** і націсніце **Add Record**.
3. Абярыце **CNAME**.
4. У полі **name** увядзіце свой дамен або паддамен, напрыклад `notes.mysite.com`.
5. У полі **target** увядзіце `publish-main.obsidian.md`. Не дадавайце сюды свой асабісты суб-URL: Obsidian Publish возьме яго з вашых налад.
6. Пераканайцеся, што **proxy status** уключаны. Па змаўчанні ён уключаны.
7. Перайдзіце ў **SSL/TLS** і ўсталюйце рэжым шыфравання SSL/TLS «Full», каб сертыфікат SSL/TLS наладзіўся аўтаматычна.

> [!note] Заўвага
> Каб перанакіроўваць на Obsidian Publish і `mysite.com`, і `www.mysite.com`, стварыце [Page Rule](https://support.cloudflare.com/hc/en-us/articles/200172336-Creating-Page-Rules) з такімі параметрамі:
>
> - URL match: `www.mysite.com/*`
> - Forward URL - 301 Permanent Redirect
> - Redirect URL: `https://mysite.com/$1`
>
> Пасля стварэння правіла дадайце CNAME-запіс для `www.mysite.com` гэтак жа, як для `mysite.com`.

**Obsidian:**

1. Адкрыйце Obsidian на камп'ютары.
2. Адкрыйце [[Меню каманд|меню каманд]] і выканайце **Апублікаваць: Публікацыя змен...**.
3. У акне **Публікацыя змен** абярыце **Налады сайта** ![[lucide-cog.svg#icon]].
4. Побач з **Уласны дамен** абярыце **Наладзіць**.
5. У полі **Уласны URL** увядзіце адрас свайго дамена або паддамена. Не пішыце `www.` у гэтым полі.

> [!note] Заўвага
> Калі пасля налады ўласнага дамена ўзнікае бясконцае перанакіраванне, хутчэй за ўсё, у CloudFlare усталяваны рэжым шыфравання «Flexible» замест «Full».

## Налада праз проксі

Наладзіць SSL/TLS для ўласнага дамена можна таксама праз уласны вэб-сервер.

Калі на вашым дамене або паддамене ўжо працуе сайт, гэты спосаб дазваляе загружаць сайт Obsidian Publish па пэўным шляху URL, а не размяшчаць яго на ўвесь дамен.

Перанакіроўвайце праз проксі ўсе запыты па гэтым шляху на `https://publish.obsidian.md/serve?url=mysite.com/my-notes/...` і ўкажыце той жа шлях у наладах сайта ў Obsidian, усталяваўшы **Уласны URL** у `mysite.com/my-notes`.

Таксама можна размясціць Obsidian Publish як суб-URL вашага сайта, напрыклад `https://mysite.com/my-notes/`. Для гэтага трэба мець уласны сервер і перанакіроўваць праз проксі ўсе запыты на наш сервер `https://publish.obsidian.md/`.

Ніжэй прыведзены не ўсе магчымыя варыянты налады проксі, а толькі самыя распаўсюджаныя.

### NGINX

Дадайце ў канфігурацыю NGINX наступнае:

```nginx
location /my-notes {
  proxy_pass https://publish.obsidian.md/serve?url=mysite.com/my-notes/;
  proxy_ssl_server_name on;
  proxy_set_header Host publish.obsidian.md;
}
```


Некаторыя карыстальнікі паведамляюць, што можа спатрэбіцца дадаць `$request_uri` у proxy pass:

```nginx
location /my-notes {
  proxy_pass https://publish.obsidian.md/serve?url=mysite.com/my-notes$request_uri;
  proxy_ssl_server_name on;
  proxy_set_header Host publish.obsidian.md;
}
```

### Apache

Дадайце ў `.htaccess` наступнае:

```htaccess
RewriteEngine  on
RewriteRule    "^my-notes/(.*)$"  "https://publish.obsidian.md/serve?url=mysite.com/my-notes/$1"  [L,P]
```

> [!note] Заўвага
> Павінен быць уключаны `mod_rewrite`; таксама можа спатрэбіцца наладзіць [SSLProxyEngine](https://stackoverflow.com/questions/40938148/reverse-proxy-for-external-url-apache)

### Netlify

У `netlify.toml` [наладзьце перанакіраванні](https://docs.netlify.com/routing/redirects/#syntax-for-the-netlify-configuration-file):

```plain
[[redirects]]
  from = "https://mysite.com/my-notes/*"
  to = "https://publish.obsidian.md/serve?url=mysite.com/my-notes/:splat"
  status = 200
  force = true
```

### Vercel

У `vercel.json` [наладзьце rewrites](https://vercel.com/docs/configuration#project/rewrites):

```json
{
  ...

  "rewrites": [
    {
      "source": "/my-notes/",
      "destination": "https://publish.obsidian.md/serve?url=mysite.com/my-notes"
    },
    {
      "source": "/my-notes/:path*",
      "destination": "https://publish.obsidian.md/serve?url=mysite.com/my-notes/:path*"
    }
  ]
}
```

### Caddy

```plain
mysite.com {
  encode zstd gzip
  handle /my-notes* {
    reverse_proxy https://publish.obsidian.md {
      header_up Host {upstream_hostport}
    }
    rewrite * /serve?url=mysite.com{path}
  }
}
```

### Traefik

Гэты мінімальны фрагмент канфігурацыі перанакіроўвае `mysite.com` на Obsidian Publish.
Поўны прыклад глядзіце ў [дакументацыі Traefik](https://doc.traefik.io/traefik/routing/overview/).

```yaml
http:
  routers:
    mysite:
      rule: Host(`mysite.com`)
      service: obsidian-publish
      middlewares:
        - "publish-headers"
  services:
    obsidian-publish:
      loadBalancer:
        servers:
          - url: https://publish.obsidian.md
  middlewares:
    publish-headers:
      headers:
        customRequestHeaders:
          Host: "publish.obsidian.md"
          x-obsidian-custom-domain: "mysite.com"
```

### Падтрымліваемыя HTTP X-загалоўкі

Калі ваш проксі-сэрвіс не дазваляе параметры запыту ў шляху, можна выкарыстоўваць `https://publish.obsidian.md/` з загалоўкам `x-obsidian-custom-domain`, у якім указаны URL вашага сайта `mysite.com/my-subpath`.

## Перанакіраванне са старога сайта на ўласны дамен

Каб перанакіроўваць наведвальнікаў са старога адраса на `publish.obsidian.md` на новы ўласны дамен, падчас налады дамена ўключыце параметр **Перанакіроўваць на ўласны дамен**.

## Вырашэнне праблем

Калі пасля налады ўласнага дамена вы адкрываеце свой сайт, які раней наведвалі па спасылцы `https://publish.obsidian.md/slug`, можа спатрэбіцца ачысціць кэш браўзера, каб некаторыя рэчы (напрыклад, шрыфты, графы ці доступ па паролі) працавалі правільна. Гэта звязана з абмежаваннямі бяспекі паміж даменамі ў сучасных браўзерах. Добрая навіна ў тым, што чытачы вашага сайта не сутыкнуцца з гэтай праблемай, калі наведвальнікі карыстаюцца толькі ўласным даменам.
